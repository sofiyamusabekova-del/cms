# PRD — Visual Site Builder

## 1. Краткое описание

Visual Site Builder — это визуальный конструктор сайтов, находящийся между WordPress, Tilda и Elementor.

Цель продукта — позволить пользователю без знания HTML/CSS собирать многостраничные сайты из готовых секций, редактировать контент и стили через визуальные контролы, работать с мультиязычностью и блогом, а затем экспортировать проект как обычный статический сайт.

Ключевой принцип MVP:

> Не строить полный клон Elementor/Webflow. Создать стабильный block-based конструктор с ограниченной вложенностью и понятным интерфейсом.

---

## 2. Для кого продукт

### Основная аудитория

- начинающие веб-разработчики;
- преподаватели и ученики frontend-курсов;
- дизайнеры без глубоких знаний frontend;
- малый бизнес;
- фрилансеры;
- владельцы небольших сайтов;
- агентства, которым нужны быстрые типовые сайты.

### Основная задача пользователя

Пользователь должен суметь пройти путь:

1. Создать проект.
2. Создать или выбрать страницу.
3. Добавить готовые секции.
4. Изменить их порядок drag-and-drop.
5. Изменить текст и изображения.
6. Настроить внешний вид без ручного CSS.
7. Проверить Desktop / Tablet / Mobile.
8. Настроить SEO.
9. Добавить другие языки.
10. Экспортировать готовый сайт.

## 3. Основные продуктовые принципы

### 3.1 Простота важнее полной свободы

Пользователь не работает напрямую с DOM и не строит бесконечные контейнеры.

Основная структура:

```text
Page
 ├─ Section
 │   ├─ Element
 │   └─ Element
 ├─ Section
 └─ Section
```

### 3.2 Готовые блоки вместо сборки каждого div

В MVP используются готовые секции:

- Header

- Features
- Services
- Text + Image
- Gallery
- Statistics
- Pricing
- Team
- Reviews
- FAQ
- CTA
- Contacts
- Map
- Blog Preview
- Footer

### 3.3 Визуальные настройки вместо CSS

Пользователь управляет стилями через:

- slider;
- numeric input;
- color picker;
- segmented controls;
- select;
- toggle;
- кнопки выравнивания;
- выбор числа колонок.

### 3.4 Preview должен соответствовать экспорту

Одна модель данных должна использоваться редактором, предпросмотром и системой экспорта.

## 6. Визуальные контролы

### Slider + numeric input

Использовать для:

- padding;
- margin;
- gap;
- max-width;
- width;
- height;
- min-height;
- border-radius;
- font-size;
- line-height;
- letter-spacing;
- opacity;
- blur;
- shadow intensity;
- animation duration.

Формат:

```text
Padding
[-] [────────●────] [48] px [+]
```

Каждый slider должен иметь:

- min;
- max;
- step;
- numeric input;
- reset.

### Spacing control

Поддержать режимы:

```text
[✓] Link values

Top     40
Right   24
Bottom  40
Left    24
```

### Не использовать slider там, где есть более понятный контрол

Alignment:

```text
[Left] [Center] [Right] [Justify]
```

Columns:

```text
[1] [2] [3] [4] [5] [6]
```

Display:

```text
Block | Flex | Grid
```

Background:

- color;
- gradient;
- image;
- overlay.

## 7. Responsive

Viewport modes:

- Desktop
- Tablet
- Mobile

Большинство размерных свойств могут иметь отдельные значения.

Пример:

```json
{
  "fontSize": {
    "desktop": 52,
    "tablet": 42,
    "mobile": 32
  }
}
```

Если значение отсутствует:

```text
mobile -> tablet -> desktop
```

используется наследование.

## 13. Autosave

Изменения сохраняются автоматически через debounce.

UI состояния:

```text

Saved
Error
```

Для учебного MVP допустимо начать с localStorage, затем заменить на backend.

## 16. AI — расширение, а не основа MVP

AI может позже:

- предложить структуру страницы;
- выбрать существующие блоки;
- генерировать тексты;
- переводить;
- создавать SEO;
- переписывать контент.

AI должен генерировать структуру через существующий Block Registry, а не произвольный HTML.

Пример:

```json
{
  "blocks": [
    { "type": "hero", "variant": "split" },
    { "type": "services", "variant": "cards" },
    { "type": "reviews", "variant": "grid" },
    { "type": "contacts", "variant": "default" }
  ]
}
```

---

## 17. Что НЕ входит в MVP

Не делать на первом этапе:

- полный аналог Elementor;
- бесконечную DOM-вложенность;
- произвольное absolute positioning;
- сложный visual CSS editor;
- animation timeline;
- marketplace plugins;
- ecommerce;
- роли и команды;
- сложную облачную публикацию;
- совместное редактирование;
- полноценный AI website generator.

---

## 18. Критерии готовности MVP

MVP считается успешным, если пользователь может:

1. Запустить приложение.
2. Создать страницу.
3. Добавить несколько блоков.
4. Изменить их порядок.
5. Отредактировать текст.
6. Изменить основные стили визуальными контролами.
7. Настроить разные значения для mobile/tablet/desktop.
8. Переключить язык.
9. Настроить основные SEO-поля.
10. Открыть preview.
11. Перезагрузить страницу и не потерять сохранённый проект.
12. Экспортировать базовый статический сайт.

---

## 19. Учебный режим разработки

Проект специально разбивается на короткие итерации.

Каждый учебный спринт:

- 5–10 небольших задач;
- после спринта проект обязан запускаться;
- существующие функции не должны ломаться;
- ученик проверяет результат вручную;
- только после проверки переходит к следующему спринту.

Это позволяет работать даже при ограниченном количестве токенов в AI-агентах.
